    Front matter

    How to Use This Book

    Part I is for reading, and you may skip it and start at Part II, coming back to it later. From Part II on, the book is for doing: every idea comes with code, and the best way to learn it is to type that code in, run it, and then break it. Change a number and see what happens. Delete a line and read the error message. The networks in this book are small enough to train in seconds or minutes on an ordinary laptop, so experimenting is cheap.

    What you need

    You need Python 3.9 or later and a handful of libraries:

    pip install torch torchvision numpy scipy scikit-image matplotlib

    The PyTorch website, https://pytorch.org, gives the exact command for your operating system and hardware. If you would rather not install anything, a free hosted notebook service such as Google Colab already has all of these libraries installed and offers a graphics processor.

    A graphics processor (GPU) helps but is not required. Chapter 10 shows how the code picks the best hardware available, whether an NVIDIA card, an Apple-silicon Mac, or the ordinary processor, and everything in the book runs on all three. Only the speed changes.

    The datasets, the pretrained AlexNet weights and the sample photographs are all downloaded automatically, by the code that first uses them, into a folder called data.

    Each listing’s name is printed in small type at its top right, like arr_dot above. It is the name of the block in the chapter’s code file, and the exercises use it to say which listing to change. Within a chapter, each listing builds on the ones before it, so run them in order. Each chapter starts fresh: it loads its own data and defines what it needs, apart from a few small helper functions that are introduced once and then reused, such as montage_plot for drawing many images at once. A chapter that reuses one says so, and the chapter’s code file defines it again so that the file runs on its own.

    Random numbers play a big part in deep learning, from the starting weights to the order of the training examples. The code fixes the random seed so that it gives the same results every time it runs, but different hardware generates random numbers differently, so your numbers will not exactly match the ones printed here. They should be close, and they should tell the same story.

    Python beyond the basics

    The book assumes basic Python: variables, lists, loops, if and functions. A few other pieces of the language turn up along the way, and here is all you need to know to read them:

    • f'{x:.3f}' is an f-string: the value of x is written into the text, here with three decimal places.

    • with torch.no_grad(): runs the indented lines inside a setting, here “do not record for gradients,” and switches it off afterwards.

    • [f(x) for x in items] builds a list in one line; without the brackets, as in sum(f(x) for x in items), the values are made one at a time and used as they come.

    • lambda x: x * 2 is a function without a name, handy when one is needed for a single line.

    • a, b = pair unpacks two values at once, and **options passes on whatever keyword arguments a function was given.

    • A class bundles data with the functions that work on it; you will only need to read one, in Chapter 11.

    Conventions

    Code and names from code appear in a typewriter font. Pictures and plots are drawn with matplotlib (plt.figure, plt.imshow, plt.plot, plt.subplot for a grid of panels); the book uses only a handful of its commands, and you can treat them as recipes. Throughout the book, X holds the inputs (images), Y the correct answers (labels), and X_test and Y_test the examples held back for testing. Weights are kept in a list called w, and the device the computation runs on is called device.

    Terms are set in italics where they are defined, and the index points to those definitions.
